# 接口说明与验证状态

记录日期：2026-10-03。"已验证"指在本机用真实 Key 实测过；"文档"指百炼帮助中心页面所述；"未验证"就是没试过或没查到。

## 接口

| 用途 | 地址 | 状态 |
|---|---|---|
| 合成 | `POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer` | 已验证（不需要 WorkspaceId） |
| 复刻音色 | `POST https://dashscope.aliyuncs.com/api/v1/services/audio/tts/customization` | 已验证（文档示例用 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com`，通用域名也可用） |
| 语音识别（逐词时间 + 文字核对） | `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation` | 已验证（模型 `qwen-audio-3.1-asr-flash`；文档示例用 `{WorkspaceId}` 域名，通用域名也可用） |

鉴权：`Authorization: Bearer <API Key>`。

识别请求体：`{"model":"qwen-audio-3.1-asr-flash","input":{"messages":[{"role":"user","content":[{"type":"input_audio","input_audio":{"data":"data:audio/wav;base64,…"}}]}]},"parameters":{"format":"wav","sample_rate":"16000"}}`。
返回里 `sentence.words[]` 每个词有 `text`、`begin_time`、`end_time`（毫秒）、`punctuation`、`fixed`；响应嵌套了两层 `output`，代码里递归查找带 `words` 的节点。逐词时间戳不需要额外参数。

合成请求体（固定参数见 `scripts/voice/common.py`）：

```json
{"model": "qwen-audio-3.1-tts-flash",
 "input": {"text": "…", "voice": "<voice_id>", "format": "wav", "sample_rate": 48000,
           "instruction": "像朋友聊天一样自然随意的口语，不要播音腔，语速较快，句与句之间保留自然的停顿，语气轻松带笑意"}}
```

返回 `output.audio.url`（约 24 小时有效），下载后用 ffmpeg 转一遍：接口返回的 wav 头里时长字段不准。

复刻请求体：`{"model":"voice-enrollment","input":{"action":"create_voice","target_model":"qwen-audio-3.1-tts-flash","prefix":"myvoice","url":"data:audio/mpeg;base64,…"}}`，返回 `output.voice_id`。

## 已验证的结论

- **600 字单次合成成功**（耗时约 13.5 秒，音频 103 秒，识别字数与原文一致，没有被截断）。
- **限流看的是"每秒提交数"**：6 路瞬间同时提交，每轮只放行 3 路，其余立即返回 `429 Throttling.RateQuota`；每 0.6 秒错开提交，6 路全部成功；瞬间 6 路加"遇 429 等 2 秒重试"也全部成功，整批 8.8 秒。
- **偶发连接错误**：测试中出现过一次 `RemoteDisconnected`，所以连接错误要当作可重试。
- **指令参数用单数 `instruction`，放在 `input` 里。** 同一文案，强指令下单数写法音频缩短约 12%，复数 `instructions` 只变不到 1%，所以复数几乎无效（靠音频变化推断，文档的 Qwen-Audio 参数页没抓到原文）。
- **语速措辞对照**（同一 141 字文案、同一音色）：很快 约 7.8 字/秒、停顿几乎消失；稍快 约 6.6 字/秒、保留停顿；偏快 约 6.0 字/秒。
- **现用"语速较快"**（2026-10-03 用户试听后从"稍快"改来）：同一篇 280 字文案各合成一次，稍快 6.87 字/秒、55.4 秒；较快 7.16 字/秒、53.7 秒；停顿都是 25 处、合计约 11 秒。差距约 4%，只有一次样本，同一指令两次合成本身也有波动。
- **情绪标签**（如 `[excited]`）在这个模型上会生效；**句首的标签没有被念出来过，句中的出现过一次被念成 "Happy"**（2026-10-05，一个放在逗号后面的 `[happy]`）。10-03 用户试听后觉得"太像 AI"，所以当时只留问句标签；10-05 再试：同一篇 1550 字，不加标签只靠加强的整体描述，用户听后说"效果不好，还是标签的好"。**现在的做法**：默认用标签，兴奋为主、1–3 种，只加句首，段首和长段内部沿用上一个情绪（见 guide.md 第 4 步）。
- **标签的几次对比**（同一篇约 1550 字，用户听的结论）：24 处、含句中标签 → 太碎，读起来割裂；12 处（兴奋 6、开心 4、委屈 2）、整篇一次合成 → "好多了"；无标签 → 不好；12 处全换成兴奋 → 可以；分 5–8 段合成 + 14 处（兴奋 7、开心 4、委屈 3）+ 问句标签 → "好多了"。逐句沿用（每句都补标签）约每 25 字一个标签，**没有听过效果**；现在默认的 auto 沿用只补到约 28 个标签，**也还没听过**。
- **只靠描述控制语速的效果有限**（2026-10-05，同一篇 1550 字、同一音色、14 处标签，只改指令里的语速词）：偏快 294.5 秒，较快 289.3 秒，差 5 秒，各段语速的变化都在 0.2 字/秒以内，和同一指令两次合成的波动同量级。正常语速那次换了音色，不能直接比。要明显变快得用"很快"（停顿几乎消失）或合成后加速（会动原声，需要用户同意）。现用"较快"。
- **一次合成的长度**：整篇 1551 字一次请求成功 3 次（约 282 秒的音频，用时 30 秒）；488、501 字的段稳定。再长没测。所以段字数上限放宽到 1000。
- **分段对结果的影响**：整篇一次合成，各段语气最连贯；分段合成每段独立生成，各段语速会不一致（实测最慢 5.7、最快 7.5 字/秒），段与段交界的语气也可能不同。结尾一段几乎每次都最慢、音高最低。
- **品牌词读法不稳**：OLDX 每次合成、每段都可能读成不同的样子（识别成 Odex、Old X、O L D X 等）。没有验证过任何纠正办法。
- **问句标签**（2026-10-03，用户要求问句带疑问语气）：文档列出的标签里没有专门的"疑问"标签。同一段含两个问句的文字试了 `[curious]`、`[questioning]`、`[confused]`、`[doubtful]`、`[疑问]`，都没有被念出来，识别文字都与原文一致。音高测量（粗略）：`[curious]` 让问句音高抬得最多（"那怎么办？"句尾比整句高 47 Hz，无标签为 -5 Hz；第二个问句整句中位 256 Hz，无标签 171 Hz），`[confused]` 次之，`[questioning]`、`[doubtful]`、`[疑问]` 接近无标签；`[疑问]` 还让整段变慢（13.4 秒，其余 9.2–10.5 秒）。所以用 `[curious]`。**没验证的**：听感是否自然（要用户试听）；标签是否会连带影响问句后面的那一句（文档说控制类标签作用到下一个标签或句子边界）。
- 复刻样本 10.2 秒、35.5 秒、单人、无背景音，效果都可用。介绍视频里对观众说的建议是 10–20 秒。
- **识别的逐词时间**：同一条 21 秒配音，与另一套本地识别工具逐词对比，词首平均相差 67 毫秒、最大 150 毫秒、P90 110 毫秒（百炼的结果略晚，不到 2 帧）；两者谁更接近真实值没有标准答案可比。21 秒音频只用 324 个输入 token。
- **识别返回的词首尾相接**：说话中间的停顿被算进前一个词里，所以停顿要用音频能量检测，不能从词间隙找。
- **识别会把数字写成阿拉伯数字**（"三十秒"→"30秒"），做文字比较前要统一数字写法（`asr.norm_text`）。
- 3 段（各约 40–50 字）实测：文字相似度均为 1.000。

## 文档里的限制

- 复刻参考音频：wav(16bit)/mp3/m4a，推荐 10–20 秒，最长 60 秒，≤10MB，采样率 ≥16kHz，至少 5 秒连续清晰朗读，不需要文本。
- 复刻本身免费；音色长期有效，1 年内未使用会被自动删除；每个账号最多 1000 个。
- 指令控制文档限制 100 字以内；本技能的指令约 50 字。

## 未验证

- 5–8 秒的复刻样本效果（只验证过 10.2 秒的）。
- 并发超过 6 路的行为；账号不同限流额度可能不同。
- 一次合成很长的文字（整篇约 1500 字）时，语气是否始终稳定：用户听过，说"好多了"，但没有逐段的数据对比。
- 逐句沿用情绪标签（`carry: sentence`）和默认的 `auto` 沿用的实际听感：写好了，没有听过。
- 文档里 Qwen-Audio 合成的 HTTP 参数页原文（抓取到的只是导航，没有正文）。
- 识别：换音色、多语种、几分钟长音频时，时间戳是否同样稳定；识别接口的限流额度（目前按段并发 + 每 0.5 秒一次提交，没触发过限流）。
- 识别单次大小上限 10MB（文档所述）；脚本按段识别并转成 16k 单声道，超限会报错提示，未实测过超限。
- 删除已复刻音色的接口用法（需要时再查文档，不要猜）。
