# 提示词编排规则

写 `avatar/prompt_src.json` 之前读。目标：让每一段的动作"从这段口播里长出来"，两只手都有事做、有起有落，身体跟着带一点，并且不碰嘴。

这些规则对任何图片、任何文案都一样用；具体写什么动作，由这张图和这段话决定。

## 一条硬规则

**不写任何与嘴部有关的描述。** 微笑、笑意、嘴唇、口型、换气、表情、神态、"露出……的笑"、情绪形容词（亲切、惊喜、无奈、生气……）一律不写——画面描述、双手描述和动作编排都不写；脚本会拦。嘴怎么动由云端应用和音频负责。

理由：早期版本在节拍里反复写"嘴唇自然闭合"、在开头写"带着笑意"，结果有一段约 10 秒说话时嘴始终闭着。

所以**情绪只能写成动作**：文案在吐槽，就写"手掌在桌面上轻拍一下"，不写"生气地"。

## 写之前先做三件事

1. **看图，读出"手能去哪"。** 除了人物外貌、发型、衣着、佩戴物、景别、背景和灯光，重点回答三个问题，后面的动作只从答案里选：
   - **手可以落在哪**：桌面、腿上、腰侧、身前交握，还是只能落到画面下沿以外。
   - **手边有什么能碰的**：桌面、扶手、手里拿着的东西。佩戴物（眼镜、耳饰、发夹、手表、麦克风）不碰。
   - **手的活动范围多大**：往上到哪、往两边到哪会出画面。

   - **身体能动多大**：上身朝向、肩线、头的位置，头顶和两侧留了多少空间。

   同时写下两只手在图里的原姿态：各在什么位置、掌心朝向、手指状态。"画面左侧／右侧"一律按观众看画面的方向，避免和人物的左右手混淆。只写图上看得见的，不猜。
2. **通读全文**（项目目录里的 `copy.txt`）：弄清结构和每一处的语气——哪里在平静地讲，哪里在强调，哪里在吐槽、感叹、发问。配音阶段留下的情绪标签（`emotions.json`）也是线索。
3. **看 `plan.json`**：每段的时长、逐词时间（`words`，相对本段起点的秒数）。动作按这些时间排。

## 画面描述（scene）和双手的原姿态（hands）

这两项由看图写成，每一段都会带上：

- `scene`：一两句话，写人物的发型、衣着、佩戴物；人物在画面里的位置和姿态、景别；背景左侧有什么、右侧有什么、灯光色调。
- `hands`：分别写"画面左侧的手""画面右侧的手"在图里的位置、掌心朝向和手指状态。
- `posture`（可选，建议写）：身体的原姿态——上身朝向、肩线、头的位置。例："上身正对镜头坐直，双肩水平，头在画面正中。"

镜头固定、视线看向镜头、画面和光线保持稳定等通用要求由云端应用自动加入，这里不要写。

## 两只手怎么写

以前的写法是"一只手做手势，另一只手同时轻轻摆动"。成片里那只"轻轻摆动"的手基本不动——实测有一条片子，一只手 82% 的帧近似静止。弱动作等于没写。所以：

### 每个节拍，两只手各有一个角色

| 角色 | 是什么 | 怎么写 |
|---|---|---|
| 主手 | 做这句话的主要手势 | 动作清楚、有位移 |
| 副手 | 做一件自己的事 | 一个看得见的动作：落到某处、掌心向上托着、叉在腰侧、收到身前、在落点上轻点 |
| 休息 | 落到图里读出的某个落点歇一拍 | 写清落到哪；之后要抬回来 |

- "轻轻摆动""手指一张一合"只能作为补充，不能是一只手在这个节拍里的全部内容。
- **两只手轮流当主手**，不要总是同一只。
- 不写"停在原位""悬在半空"——想让手歇着，就让它落到一个地方。
- 双手一起做的动作（一起展开、一拍手、一起托起）照常可以用，和上面的分工交替着来。

### 动作跟着这句话的性质选

| 这句话是 | 动作方向 | 例子（按图里有什么来换） |
|---|---|---|
| 平静叙述、停顿 | 起落 | 手落到桌面或腿上，停一拍，再抬起 |
| 强调、下结论、吐槽 | 有落点的动作 | 轻拍桌面、双手一拍、拳头敲掌心、手指在桌面点两下 |
| 无奈、不屑、得意、开心 | 对应的肢体动作 | 摊手耸肩、甩一下手、单手叉腰、握拳上举小振 |
| 数量、对比、步骤 | 比量 | 两手比宽窄、比高低；一只手当台面，另一只在上面点 |
| "我""这个""那边" | 指向 | 指自己、指画面一侧或下方 |
| 列举、信息密集 | 小幅度、跟节奏 | 一只手随每一项轻点，另一只托着 |
| 打招呼、收尾 | 挥手、点头、掌心向上在身前托起 | |

有落点的动作要用图里真有的落点：有桌面才拍桌面；没有就换成双手一拍、拳头敲掌心，或者手落到画面下方再抬起。

### 有起有落，有大有小，不重复

- 手不要从头举到尾。平静的句子和停顿里让手落下歇一拍，重音来了再抬起。
- 幅度有小、中、大的变化，大的留给重音。
- 同一个手势不连着用，全片也不要翻来覆去只用一两个。
- 内容特别密的段落（报一串数字、念清单）可以少动，不必硬加起落。

### 逐段读着写

每一段先读它在讲什么、是什么语气，再给每一句选动作。**不要写一个按关键词套动作的脚本来批量生成**——那样出来的手势翻来覆去就是那几个，和内容对不上。`build_prompts.py` 只负责校验。

## 身体也要动

只写手，人会像钉在原地：手在比划，肩膀和上身一动不动。真人说话时身体会自然跟着带一点。所以每个节拍其实有三层——**手、头、身体（肩膀和上身）**。

- **不是每拍都写身体。** 大约每两三个节拍带一次，其余只写手和头；每拍都写，人会晃个不停。
- **跟着这句话的性质选：**

  | 这句话是 | 身体怎么动 |
  |---|---|
  | 强调、下结论 | 点一下头，或肩膀轻轻一沉再放松 |
  | 疑问 | 头侧倾，同侧肩膀略抬 |
  | 吐槽、摊手 | 耸一下肩，头向一侧一偏 |
  | 兴奋、庆祝 | 肩膀轻快地一颤，上身左右轻晃 |
  | 转折、指向一侧 | 头略偏向那一侧再回正，眼睛仍看镜头 |
  | 列举 | 上身随每一项轻点一下 |
  | 平静叙述、停顿 | 重心慢慢从一侧移到另一侧，肩膀放松 |

- **身体跟着手走。** 顺着主手的方向带一点；手落下歇着的时候，可以让身体接一个小动作。头、手、身体不要在同一拍都做大的。
- **只写左右和上下，不写前后。** 不写“上身前倾”“向后一靠”“探身”，手也不写“向前推出”“伸向镜头”——人一朝镜头靠近或远离，模型就把它做成推近拉远，整幅画面跟着放大缩小，背景里的字和物件会糊成重影（实测：一段里写了“上身微微前倾”，那几秒画面被推近，背景的字牌变成了两层）。脚本会拦。需要“推近强调”的地方留给包装阶段：在成片里用代码对人物画面做缩放，稳定、可控，还能随时改。
- **宁可少，不可大。** 身体一动，段与段的接缝更容易露出来，人脸和背景也更容易出错。幅度以"看得出在动"为限：头和肩不出画，不转成侧脸，不明显靠近或远离镜头。
- **每段结束前上身回正**，和手一起回到图里的姿态。

## 节拍的格式

每行一个节拍，格式固定（脚本按它校验）：

```
0.00–0.30 保持<Picture 1>的原姿态：画面左侧的手抬在……，画面右侧的手抬在……，两只手保持轻微的自然晃动。
0.30–1.40「大家好」：画面右侧的手向外挥动，画面左侧的手落到桌面上，上身随挥手轻晃。
1.40–3.20「今天聊聊」：画面左侧的手抬起、掌心向上在身前托起，画面右侧的手收到身前。
3.20–4.60「最重要的」：点一下头，画面右侧的手的食指向下点一下，画面左侧的手托着。
……
12.00–12.40 回到原姿态附近：画面左侧的手和画面右侧的手回到抬起的位置，手指放松，仍保持轻微的自然晃动。
```

- 时间是**本段内**的秒数（用 `plan.json` 里每个词的 start/end）；「」里的关键词必须是本段台词里的词。
- **第一个节拍**写保持<Picture 1>的原姿态（`<Picture 1>` 指用户的口播图片，照这个写法写），**最后一个节拍**写回到原姿态附近。每一段的开头和结尾都要回到图片里的姿态，段与段才能接上——所以"落下"只安排在一段的中间，结尾前要抬回来。
- 动作量跟语速走：语速偏快时，一个手势覆盖一个短语，不要一个字一个动作。平均每秒不超过约 1.3 个节拍。

## 底线

- 不写嘴和表情（硬规则）。
- 手不高过下巴、不伸向镜头、不挡脸。
- 不写具体手指数（"伸出三根手指"会出错，改用手掌或食指示意）。
- **不用比喻。** 不写"像拿着话筒""像端着杯子""像捧起一摞东西""像敲键盘一样"——模型会把比喻里的东西画出来，手里凭空多出一个物件（实测：写了"像捧起所有东西"，成片里手上真的多了一团东西，重跑一次还在）。直接写手怎么动："握拳抬到胸前""掌心向上并拢向前一送""手指交替起落"。
- 不触碰脸、头发和佩戴物。
- 不写镜头运动、转身、站起；视线不离开镜头。
- **不写任何会让人物在画面里变大变小的动作**：前倾、后仰、后靠、探身、手伸向镜头。推近、拉远、放大这类运镜一律不交给视频模型，留到包装阶段做。

## 台词（lines）

`lines[i]` 写这一段对应的**原文**（取自 `copy.txt`，用 `plan.json` 里每段的首尾词定位）。脚本把它和这一段的识别文字比较，相似度低于 0.9 就报错，防止把别的段落的话写进来。

## 校验和效果

`build_prompts.py` 分两类：

- **会拦的**：格式和时间、关键词不在台词里、嘴和表情词、具体手指数、比喻（"像……"）、镜头运动、身体或手朝镜头前后移动（前倾、后靠、探身）、触碰脸和佩戴物、视线离开镜头、首尾没有回到原姿态、超长。
- **只提示的**：某个节拍没写两只手、让手停在半空、一只手老是只有弱动作、主要手势总是同一只手、一整段没有起落、相邻节拍手势重复、一整段没写身体动作。

提示不拦截：云端模型不会逐字照做，没必要把写法卡死。看到提示就判断一下，该改的改，有理由的可以留。

同样的道理，成片里的手也不会和写的一模一样。质检给出的"手部静止比例"只是参考：手偶尔停一下、某个动作没做出来，都可以接受；只有一只手整段整段不动时，才值得改那一段的写法重跑。

## 要图片时顺带看一眼

每一段的开头和结尾都会回到图里的姿态，手能做什么也取决于图：

- **最理想**：正面、双手自然放在身前或桌面，画面里看得见桌面或留出了腰部以下的一点空间——手有地方落，起落和拍、点这类动作才做得出来；头顶和两侧留一点空，身体才有地方动。
- **能用但受限**：双手抬在空中的瞬间图，或画面下沿刚好切在胸口的图。手没有看得见的落点，"落下"只能落到画面外。
- 遇到受限的图，告诉用户一句这张图的限制和更合适的图是什么样，由用户决定，不替他拒绝。
