# 第二阶段：数字人口播视频

把"一张口播图片 + 一段配音"变成一条数字人口播视频。配音和文案由第一阶段产出，放在共用的项目目录里；这一阶段只负责人物视频，字幕、图形动画等包装在第三阶段做。

脚本路径相对本技能目录。项目目录（下文称 `workdir`）默认是最近一次的项目：

```
python scripts/voice/project.py latest        # 打印最近项目目录
```

需要的前置：`<workdir>/copy.txt`、`<workdir>/out/merged.wav`、`<workdir>/out/words.json`。缺任何一个，先回到第一阶段补上，不要自己估时间或另录配音。

## 红线

- **密钥不回显**，只说来源；**不从聊天记录、日志里翻密钥**，没有就问用户。
- **不用 `ultra` 实例**：用户只授权过 `plus`。失败或显存不足时报告，由用户决定，不自行升级。
- **不改图片内容**：只允许按比例中心裁剪（并告诉用户裁了多少），不美化、不换背景。
- **不改文案**，提示词里的台词用原文。
- 提交（花钱）前用一句话告诉用户段数和预计费用（见下）；用户这次的请求里已经明确说了"开始跑"就直接提交，否则等一个确认。

## 流程

### 0. 先要图片，再查环境

1. **先向用户要口播图片**，第一件事，其他都不先问。图片决定画幅、尺寸和提示词，所以放在最前面。
2. 查环境：

   ```
   python scripts/avatar/check_setup.py
   ```

   - 退出码 3：没有 RunningHub Key。把脚本输出的引导文案**原样**发给用户并停下等待（要求用户获取后**直接粘贴到对话输入框**，其余由你处理）。**不要让用户打开终端、设置环境变量或运行任何命令**，所有命令都由你来执行。用户发来后**直接保存并告知**，不再追问：用 Write 工具写入 `~/.runninghub/api_key`（不要有多余内容），运行 `python scripts/avatar/check_setup.py --lock`，然后只说一句"已收到并保存在本机（仅你的账户可读），之后不用再发；想删除告诉我"，不复述 Key。
   - 退出码 5：还没记录会员档位。用中文问用户**一次**"你的 RunningHub 是哪一档会员"，把脚本输出的档位表列给他选，由你执行 `--set-plan`。并发数由档位决定（没记录只按 1 路）。
   - 其他情况继续。

### 1. 处理图片

```
python scripts/avatar/prepare_image.py --image <图片> --workdir <workdir> --mouth-box x0,y0,x1,y1
```

`--mouth-box` 是**你看图后给出的嘴的位置**（占画面宽高的比例，例如 `0.42,0.46,0.58,0.58`），成片质检用它定位嘴部；先看一遍图再写，不要瞎填。

- 在 16:9、9:16、1:1、3:4、4:3、21:9 里选最接近的一档，目标尺寸是该比例下约 100 万像素、边长取 32 的倍数（16:9 为 1376×768，9:16 为 768×1376，1:1 为 1024×1024，4:3 为 1184×896，3:4 为 896×1184，21:9 为 1568×672）。
- 比例不完全一致时做最大范围的中心裁剪，不拉伸。
- **必须看一眼 `avatar/image_crop_check.jpg`**（原图上画了裁剪框）：头顶、手被裁到了就告诉用户，让他换图或自己先裁；没问题再继续。图片比目标小会被放大，要把脚本的提示转告用户。
- **同时看图片里的姿态**（每一段的开头和结尾都会回到这张图的姿态）：理想是正面、双手自然放在身前或桌面、没有夸张表情；如果是"双手抬在空中、嘴正在说话"的瞬间图，告诉用户一句"这张图双手抬在空中，建议换成自然放置的图，效果会更稳；也可以直接用这张"，由用户决定，不替他拒绝。

### 2. 分段

```
python scripts/avatar/plan_segments.py --workdir <workdir>
```

只设"每段最长 14 秒"：全长不超过 14 秒就整段；否则取 ceil(总长/14) 段，在配音的**停顿**处断开，切点尽量均分，不设最短限制。找不到合适停顿才依次放宽（多一段、句末标点、词边界），宁可多一段也不切在句子中间。结果写入 `avatar/plan.json`，每段音频切成 `avatar/seg_NN.wav`。

### 3. 写提示词

先读 `references/avatar/prompt-rules.md`，再按它做三件事：看图（用 Read 工具看 `avatar/image.png`）、通读 `copy.txt`、看 `plan.json` 的每段时长和逐词时间。然后写 `avatar/prompt_src.json`：

```json
{"scene": "画面描述（看图写：人物的发型、衣着、佩戴物；位置和姿态；背景左右两侧有什么）",
 "hands": "双手的原姿态（分别写「画面左侧的手」「画面右侧的手」在图中的位置、掌心朝向、手指状态）",
 "posture": "身体的原姿态（上身朝向、肩线、头的位置；可选，建议写）",
 "lines": ["第1段台词原文", "……"],
 "motions": ["第1段动作编排（每行一个节拍：起–止「词」：动作，两只手都要写）", "……"]}
```

镜头固定、视线、画面稳定等通用要求由云端应用自动加入，你只写上面四项。

要点（细节和理由见 `references/avatar/prompt-rules.md`）：

1. **不写任何与嘴部有关的描述**（硬规则）：微笑、笑意、嘴唇、口型、换气、表情、情绪形容词一律不写。嘴怎么动由云端应用和音频负责。情绪只能写成动作。
2. **先从图里读出手能去哪**：能落在哪（桌面、腿上、腰侧、画面下方）、手边有什么能碰、活动范围多大。动作只从这里面选。
3. **每个节拍两只手各有角色**：主手做主要手势；副手做一件自己的、看得见的事（落到某处、托着、叉腰、收到身前、在落点上轻点），不是"同时轻轻摆动"；想歇着就落到一个地方。两只手轮流当主手。
4. **动作跟着这句话的性质选**：平静处让手落下再抬起；强调、吐槽处用有落点的动作（轻拍桌面、一拍手、拳头敲掌心）；数量和对比用比量；有起有落、有大有小、不重复。
5. **不用比喻**：不写"像拿着话筒""像捧起东西"，模型会把那样东西画出来；直接写手怎么动。脚本会拦。
6. **身体也要动，但只动左右和上下**：每两三个节拍带一次肩膀或头的小动作（强调处点头、吐槽处耸肩、指向一侧时头略偏、平静处重心慢慢移）；宁可少不可大，段尾回正。**不写前倾、后靠、探身，手不伸向镜头**——模型会把它做成推近拉远，画面和背景跟着出错；推近、拉远、放大这类运镜一律留给包装阶段用代码做。脚本会拦。
7. **逐段读着写**，不要用按关键词套动作的脚本批量生成。

```
python scripts/avatar/build_prompts.py --workdir <workdir>
```

脚本分两类：格式和时间、关键词不在台词里、嘴和表情词、具体手指数、触碰佩戴物、视线离开镜头、首尾没有回到原姿态这些会拦，按提示改到通过；两只手的写法（副手只有弱动作、主手总是同一只、整段没有起落、手势重复）只给提示，不拦——云端模型不会逐字照做，没必要卡死，看到提示判断一下就行。通过后提示词在 `avatar/prompts/`。

### 4. 预览，再提交

```
python scripts/avatar/run_avatar.py --workdir <workdir>          # 预览：不联网，不花钱
```

预览会列出尺寸、实例、档位对应的并发数和每段情况。然后按下面估算告诉用户预计费用：

- 参考单价（**旧模型**，768P、plus 实例）：约 **0.044–0.054 元 / 秒配音**——实测 64.5 秒、5 段合计 3.455 元（0.054）；275.6 秒、21 段合计 12.08 元（0.044）；早先 9 秒左右的 3 段是 0.045。云端应用换了模型之后，单价没有实测，新账号的接口也可能不返回费用：报预计费用时说明这是旧模型的参考价，实际以 RunningHub 后台为准。

确认后提交：

```
python scripts/avatar/run_avatar.py --workdir <workdir> --yes
```

- 并发数 = min(段数, 会员档位并发数)，多出来的段在本地排队。
- **重试按层分开，避免重复计费**：
  - 上传、下载各自重试 3 次；云端已成功时下载失败**只重下，不重新提交**。
  - 提交被并发/排队/限流拒绝，等 20 秒再提交，最多 12 次。
  - 任务失败先判断类型：余额不足、参数或权限错误直接停下报告（重试没用）；其余（含显存不足）退避后重提交一次（失败任务不计费），仍失败就报告原因，**不要自行换 `ultra`**。
  - 轮询超时不会重新提交：任务号保留在 `result.json` 的 `pending` 里。
- **断点续跑**：任务号一提交就落盘。脚本被中断、超时或部分段失败后，直接重跑同一条命令：已成功的段沿用，仍在云端的任务会被续上，只补真正失败的。想强制重做某段才用 `--only <段号>`。
- 退出码 4 是密钥被拒绝：让用户重新获取。
- 改过重试逻辑后用 `python tests/avatar/test_retry.py` 重跑模拟测试（不联网，10 种情况）。

### 5. 拼接与质检

```
python scripts/avatar/finalize.py --workdir <workdir>
```

每段按音频时长裁掉模型补的多余帧再拼接；**声音直接用项目里的原配音**，不用云端回传的音轨。质检项：分辨率、时长与配音差、黑帧和冻结候选，并生成 `avatar/seams.png`（每个接缝前后各两帧），**用 Read 工具看一眼**有没有跳变、变脸、变构图。

再做内容质检：

```
python scripts/avatar/qa_video.py --workdir <workdir>
```

它输出几类提示、一张图和一份异常时间段清单 `avatar/anomalies.json`（都是粗略指标，用来**发现该看的地方**）：

- **逐秒色彩**：每一秒的背景色和输入图片比，色相偏转超过 20° 或彩度降到图片的 55% 以下就记为异常时间段（实测：正常波动色相 ≤12°、彩度 0.9–1.7 倍；变青、变黄绿时色相偏转 26° 以上；褪成灰白时彩度 ≤40%）。同一色调下变亮、变浓不算异常。

- **嘴逐秒图 `avatar/mouth_strip.png`**：每秒一格，红 S 表示这一秒音频在说话。**必须用 Read 工具看**：说话的秒里嘴一直闭着就是问题段。帧间差分会被头部晃动干扰，漏检过，所以最终以这张图为准。
- **两只手**：每段里近似静止的帧占比，任一只手超过 60% 才标出。这只是参考：模型不会和写的一模一样，手偶尔停一下、某个动作没做出来都可以接受。
- **色彩**：某段背景色与各段中位色的色差 >25 才标出，也就是整段明显变成另一种色调的情况。

此外用 `scripts/packaging/contact_sheet.py` 每 2–4 秒抽帧，看手有没有遮脸、表情是否夸张、手形是否别扭。

**发现问题段怎么补救**：**同样的输入重跑会得到同样的结果**，所以必须改输入再用 `--only <段号>` 只重跑问题段：

- **说话时嘴一直闭着或几乎不动**：改那一段的动作编排（换几个节拍的写法或时间）再用 `--only <段号>` 重跑，并用嘴部逐秒图确认。
- **一只手整段整段不动**：把那一段里这只手的动作改成看得见位移的（落到某处、托着、在落点上轻点），让它当几次主手，再用 `--only <段号>` 重跑。偶尔停一下不用管。
- **色彩偏移**：改提示词有效（实测第 5 段色差从 6.6 降到 0.5）。

**先考虑遮盖，再考虑重跑。** 重跑要花钱，而且同样的输入常得到同样的问题。这条片子接下来要做包装（第三阶段），`anomalies.json` 里的异常可以在包装时遮盖掉：异常出现前人物缩到右下角小窗（嘴不动这类人物本身的问题则暂时隐藏人物），主画面放这几句话的要点卡，异常过后再回到全屏。只有下面这些情况才重跑：异常在片头 3 秒内、落在用户专门设计的动作上、或遮盖总时长会超过全片约 40%。不做包装、只交付数字人视频时，按下面的办法补救。

**哪些不用补救**（用户看片后定的标准）：段与段之间颜色有小幅跳变、灯光颜色有自然的变化、手偶尔停一下，都属于可以接受——切点都在说话的停顿处，正常剪辑也会有这种跳变。这些情况在交付时提一句即可，不要为它重跑。只有嘴不动、整段变成另一种色调、画面里多出明显不该有的东西、手形或人物明显出错时才补救。

每段最多补救 2 次，仍不行就如实报告。

### 6. 小结并进入下一阶段

一条龙流程里这一步不是终点：用下面的要点向用户报一句进度（尤其是 `anomalies.json` 里有没有要遮盖的时间段），然后进入包装阶段；用户只要人物视频时才在这里停下。

先给结论，再给依据，用中文：

- 一句话结论：成片路径、尺寸、时长、几段、费用。
- 分段情况：每段时长和断在哪（停顿还是别的）。
- 质检结果：脚本的几项、接缝图、嘴逐秒图和抽帧的观察，每个问题给出时间点。
- **没验证的**如实写：口型是否对准、手势细节、人物是否前后一致——脚本和静帧都判断不了，请用户播放确认。
- 提醒：Key 如果在聊天里出现过，建议重新生成。

产物都在 `<workdir>/avatar/`：`final_avatar.mp4`、`plan.json`、`prompts/`、`clips/`（各段原始视频）、`result.json`（任务号和费用）。

## 失败时怎么办

| 现象 | 做法 |
|---|---|
| 缺 `words.json` / `merged.wav` | 先回到第一阶段 |
| 某段云端失败（如显存不足） | 脚本已自动重试一次；仍失败就报告原始错误。14 秒的段在 768P 没测过，可能是这个原因，由用户决定是否把上限调小（`plan_segments.py --max 11`，需要重新写提示词）或升级实例 |
| 脚本中途被打断 / 超时 | 直接重跑同一条命令，会续上已提交的任务，不会重复计费 |
| 提交被拒（并发/排队） | 脚本会等待重试；仍不行就确认会员档位是否记录对了 |
| 密钥被拒 | 让用户重新获取并发给你 |
| 接缝有跳变 | 看 `seams.png`，指出是哪个接缝；通常是该段首尾姿态没回到原位，改那一段的动作编排后用 `--only` 重跑 |

接口、已验证数据和没验证的事项，见 `references/avatar/runninghub-notes.md`。
